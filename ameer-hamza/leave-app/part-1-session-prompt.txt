  ### How it works at runtime (`Libraries/Alert/Alert.js`)
  - **On iOS (lines 69–78),** `Alert.alert` just calls `Alert.prompt` with type
  `'default'`.
  - **`prompt` does nothing unless `Platform.OS === 'ios'` (line 154).** Its
  default `type` is `'plain-text'` (line 149).
  - **iOS button handling (lines 163–178):**
    - `style: 'cancel'` sets `cancelButtonKey` and `'destructive'` sets
  `destructiveButtonKey`.
    - `isPreferred` sets `preferredButtonKey`.
    - Any number of buttons is allowed.
    - A trailing button with no `text` is dropped.
  - **`userInterfaceStyle` is only passed to native on iOS (line 192).** The
  `.d.ts` does not mark it iOS-only, but it does nothing on Android.
  - **Android (lines 79–138):**
    - `cancelable` defaults to `false` (line 90).
    - `buttons.slice(0, 3)` (line 100): **extra buttons are silently dropped.**
    - Roles are assigned by popping from the end (lines 102–104): the last
  button is positive, the one before it is negative, and the one before that is
  neutral.
      - 1 button: positive.
      - 2 buttons: negative, positive (e.g. Cancel, OK).
      - 3 buttons: neutral, negative, positive (e.g. Later, Cancel, OK).
    - If no buttons are passed, you get a single `'OK'` (lines 98–101). On iOS
  the native side localizes "OK"; on Android it is the hard-coded string `'OK'`.
    - **`style` and `isPreferred` are ignored on Android.** The order of the
  array decides the role.
    - A dismissal without a button tap (outside tap or back press when
  `cancelable: true`) calls `options.onDismiss` (line 134), **not** the cancel
  button's `onPress`.
  - **`Alert.prompt` is iOS-only.**
    - `'login-password'` passes `{login, password}` to `onPress`. Other types
  pass a string.
    - It is a silent no-op on Android, so you would need your own `Modal` +
  `TextInput`.

  ### Promise wrapper
  ```ts
  import { Alert, Platform } from 'react-native';
  export function confirmAsync(title: string, message?: string, confirmText =
  'OK', destructive = false): Promise<boolean> {
    return new Promise((resolve) => {
      Alert.alert(title, message, [
        { text: 'Cancel', style: 'cancel', onPress: () => resolve(false) },
        { text: confirmText, style: destructive ? 'destructive' : 'default',
  onPress: () => resolve(true) },
      ], { cancelable: true, onDismiss: () => resolve(false) });
    });
  }
  // usage: if (await confirmAsync('Cancel leave request?', undefined, 'Yes,
  cancel', true)) { ... }
  ```
  Calling `resolve` more than once does nothing, so it is safe. Without
  `onDismiss`, an Android outside tap with `cancelable: true` would leave the
  promise pending forever.

  ### How screen readers announce it
  From the docs:
  - On focus, the screen reader reads the label, then the role (for example
  "button"), then the state (for example "disabled", "selected").
  - **iOS:** VoiceOver reads `accessibilityHint` after the label, but only if
  the user has hints turned on.
  - **Android:** TalkBack always reads the hint, and users can't turn it off.
  - The docs' example for `accessibilityLabelledBy` (Android) announces "Input,
  Edit Box for Label for Input Field".

  ### Grouping
  - **Focus only lands on elements with `accessible={true}`.**
  - An accessible parent becomes one focus stop, and its child `Text`s are
  combined into its default label.
  - Use this to make a whole card one stop, for example "Annual leave, 12 to 14
  October, Approved".
  - Inside an accessible container, child elements can't be focused separately.
  - Docs example: `<View><View accessible /><View /></View>`. Only the first
  child can get focus.
  - `experimental_accessibilityOrder` controls the focus order of children by
  `nativeID`. It is experimental.

  the label.
  - Hide decorative images.
  - Use `accessibilityLiveRegion` / `aria-live` (Android) for status updates
  such as "Request submitted".

  accessibilityLabel:
  - It replaces the text a screen reader would otherwise read, which by default
    is all the child Text joined together.
