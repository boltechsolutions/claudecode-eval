     Plan: Leave Requests screen (MVP)

     Context

     taimoor-farid/leave-app is still the blank Expo template (App.tsx
     placeholder, no router, no src/). We need one screen, "Leave Requests",
     driven by fixed in-code data, with approve/reject/undo behaviour. Project
     rules: React Native core only, no new packages, no edits to package.json
     dependencies. expo-router is not installed, so App.tsx renders the screen
     directly.

     Structure (all new except App.tsx)

     - src/types/leave.ts — LeaveStatus = 'pending' | 'approved' | 'rejected',
       LeaveRequest { id, name, dates, status }, HistoryEntry { id, 
       previousStatus }.
     - src/data/leaveRequests.ts — the fixed 4 rows (Ali Khan 3-5 Mar pending;
       Sara Ahmed 10-11 Mar pending; Omar Raza 17-21 Mar pending; Hina Malik 24
       Mar approved).
     - src/components/LeaveCard.tsx — name, dates, coloured status text (pending
       grey, approved green, rejected red); renders Approve/Reject only when
       status === 'pending'.
     - src/components/ActionButton.tsx — small Pressable wrapper (label, colour,
       onPress, accessibilityLabel, disabled); reused for Approve, Reject and
       Undo.
     - src/screens/LeaveRequestsScreen.tsx — state and layout.
     - App.tsx — edit to render LeaveRequestsScreen.

     Behaviour (in LeaveRequestsScreen)

     - State: requests: LeaveRequest[] (initialised from the fixed data) and
       history: HistoryEntry[] (stack).
     - changeStatus(id, next): push {id, previousStatus} onto history, then
       update that request's status.
     - Approve: calls changeStatus(id, 'approved') directly.
     - Reject: Alert.alert('Reject leave?', \Reject ${name}'s leave for
       ${dates}?`, [{text:'Cancel', style:'cancel'}, {text:'Reject',
       style:'destructive', onPress: () => changeStatus(id,'rejected')}])`.
       Cancel does nothing, so no history entry.
     - Undo: pop the newest history entry and restore that request's previous
       status. One tap undoes one action. Button disabled when history.length 
       === 0.
     - Summary line is derived from requests on each render (not stored):
       Pending: X · Approved: Y · Rejected: Z, so it always updates.
     - Both buttons disappear after any action because they render only for
       pending. Undoing returns the card to pending, so they reappear.
     - Accessibility: accessibilityLabel = Approve leave for ${name} / Reject 
       leave for ${name}, accessibilityRole="button", and
       accessibilityState={{disabled}} on Undo.
     - Layout: title and summary at the top, FlatList of cards (keyExtractor =
       id, extraData not needed because the data is replaced immutably), Undo
       button pinned at the bottom. Styles via StyleSheet. Light theme to match
       app.json.

     Notes / risks

     - Per AGENTS.md, check the RN 0.86 / Expo SDK 57 docs before finalising
       Alert and safe-area handling. Core SafeAreaView is deprecated in recent
       RN, and react-native-safe-area-context is not allowed as a new
       dependency. Fallback is manual top/bottom padding using core APIs
       (Platform, StatusBar.currentHeight).
     - Alert.alert is a no-op on web (react-native-web). Verify on iOS/Android;
       web is out of scope for the MVP.
     - No automated test framework exists, and I will not add one (no new
       packages).

     Verification

     1. npx tsc --noEmit passes.
     2. npm start and open on iOS simulator or Android (Expo Go). Check:
        - Header shows Pending: 3 · Approved: 1 · Rejected: 0.
        - Approve on Ali Khan: card turns green "approved", buttons vanish,
          header becomes 2 · 2 · 0.
        - Reject on Sara Ahmed: alert shows "Reject leave?" / "Reject Sara
          Ahmed's leave for 10-11 Mar?". Cancel leaves everything unchanged,
          Reject turns the status red.
        - Undo reverts newest action first and is disabled at start and after
          history empties.
        - Hina Malik shows green approved with no buttons.
        - Accessibility labels read "Approve leave for <name>" / "Reject leave
          for <name>" (check via the inspector or VoiceOver/TalkBack).
     3. npx expo lint is not run (it would require installing ESLint packages,
        which the project rule forbids). Ask the user if wanted.
