     Plan: "Approve all" + one-tap batch Undo

     Context

     src/screens/LeaveRequestsScreen.tsx currently approves/rejects one request
     at a time. Each action pushes one {id, previousStatus} entry onto history,
     and Undo pops a single entry. We need an "Approve all" button under the
     title (confirm via Alert, disabled when nothing is pending) and Undo must
     revert the entire Approve-all in one tap.

     Approach

     Make each history entry a batch of changes, so single actions are batches
     of one and Approve-all is a batch of N. Undo stays one pop, and the same
     code path handles both.

     1. src/types/leave.ts

     Replace HistoryEntry with a batch:
     export type StatusChange = { id: string; previousStatus: LeaveStatus };
     export type HistoryEntry = StatusChange[];

     2. src/screens/LeaveRequestsScreen.tsx

     - Import StatusChange if needed. Keep existing imports (core RN only, reuse
       ActionButton, no new packages).
     - Generalize changeStatus to a helper applyStatus(targets: LeaveRequest[], 
       next: LeaveStatus):
       - setHistory(h => [...h, targets.map(r => ({ id: r.id, previousStatus: 
         r.status }))])
       - setRequests(rs => rs.map(r => ids.has(r.id) ? { ...r, status: next } : 
         r)) (use a Set of ids)
       - Existing handleApprove/handleReject call applyStatus([request], ...).
     - Add handleApproveAll:
       - const pending = requests.filter(r => r.status === 'pending'); return if
         empty.
       - Alert.alert('Approve all?', \Approve ${pending.length} pending
         request${pending.length === 1 ? '' : 's'}?`, [Cancel, { text: 'Approve
         all', onPress: () => applyStatus(pending, 'approved') }])`
       - Alert text uses the real count, e.g. "Approve 2 pending requests?" as
         specified (use the spec's exact wording as the Alert message; title
         "Approve all").
     - handleUndo: pop last batch; setRequests maps over the batch (build
       Map<id, previousStatus>) and restores all of them at once; setHistory(h 
       => h.slice(0, -1)).
     - UI: in the header, directly below the title <Text> (above/below summary
       line: place right after title per spec "below the title"), render
       <ActionButton label="Approve all" color="#16a34a" 
       accessibilityLabel="Approve all pending requests" 
       onPress={handleApproveAll} disabled={count('pending') === 0} />.
       Match the color used for the per-card Approve button in LeaveCard.tsx
       (check it during implementation). Add alignSelf: 'flex-start' via wrapper
       if the button should not stretch (header uses gap: 6).

     Edge cases

     - Zero pending → button disabled (ActionButton already dims + blocks
       press), handler also guards.
     - Approve all then Undo → all those requests return to pending in one tap;
       earlier history entries are untouched.
     - Mixed history (single approve, then approve all) → Undo reverts
       approve-all first, next Undo reverts the single approve.

     Verification

     - npx tsc --noEmit (no lint config; don't run npx expo lint, it would
       install packages).
     - npm start and manual test in simulator/Expo Go:
       a. Fresh state: tap Approve all → alert shows the real pending count;
          Cancel changes nothing; confirm approves all, summary updates, button
          becomes disabled.
       b. Tap Undo once → all those requests are pending again, button
          re-enabled.
       c. Approve one card, then Approve all, then Undo twice → reverses in
          correct order.
       d. Reject one, Approve all (remaining) → alert count excludes the
          rejected one.
